TCCL — Contratos inteligentes

A TCCL (The Coin Cloud Language) é a linguagem dos contratos inteligentes da The Coin. Parece Python — blocos por indentação, poucas palavras-chave — mas cada valor tem um tipo declarado, cada passo custa combustível e o mesmo código dá exatamente o mesmo resultado em todos os nós.

Princípios

🧱

Tipos estritos

Toda constante, variável de estado, parâmetro e variável local declara o tipo. Não há conversões automáticas: somar int com text é erro de compilação. Uma view não pode alterar o estado, e só funções payable recebem TCN. O que é ambíguo é recusado antes de chegar à rede.

🎯

Determinístico

Não existem números de ponto flutuante, relógio, aleatoriedade nem acesso à internet. Os inteiros têm 128 bits e todo estouro (overflow) ou divisão por zero interrompe a execução. O único “tempo” é a altura do bloco (height). Por isso todos os nós chegam ao mesmo resultado.

⛽

Combustível

Cada instrução, leitura, gravação, hash ou envio consome combustível. A transação reserva um limite (max_fuel); se acabar, ou se um require falhar, tudo é revertido — o valor enviado volta, nada é gravado — e só a taxa é cobrada. Laços infinitos são impossíveis. Consultas (view) são grátis.

📜

Código-fonte on-chain

A transação de publicação carrega o código-fonte, não um binário: cada nó compila o mesmo texto com o mesmo compilador. O contrato guarda o hash do código, e qualquer pessoa lê exatamente o que vai executar — no Explorer, em cada endereço de contrato.

Instalar as ferramentas

Junto com o nó

O instalador de uma linha já instala o nó, a carteira thecoin-wallet e a ferramenta de desenvolvimento tccl:

curl -fsSL https://the-coin.cloud/install.sh | sudo bash -s -- --yes

Só quer escrever e testar contratos? Use --no-mine ou apenas os binários abaixo — o simulador tccl run não precisa de nó.

Só os binários

O pacote de the-coin.cloud/releases traz thecoind, thecoin-wallet e tccl. Ou compile:

git clone https://github.com/LucasBolla94/thecoin
cd thecoin
cargo build --release -p tccl -p thecoin-wallet
./target/release/tccl --version

Seu primeiro contrato, passo a passo

  1. Escreva o contrato. Salve como contador.tccl. Um contador que qualquer pessoa pode aumentar, com um evento e duas consultas: 
    # Meu primeiro contrato: um contador que qualquer pessoa pode aumentar.
contract Contador

state total: int
state ultimo: address

event Aumentou(quem: address, quanto: int, total: int)

action incrementar(quanto: int):
    require quanto > 0, "o valor deve ser positivo"
    require quanto <= 100, "no máximo 100 por chamada"
    total += quanto
    ultimo = caller
    emit Aumentou(caller, quanto, total)

view valor() -> int:
    return total

view quem_foi() -> address:
    return ultimo

    A primeira linha útil dá o nome do contrato. state são dados guardados na blockchain (começam em zero, texto vazio ou endereço zero); event descreve um registro que aparece no explorer; action muda o estado e é chamada por transação; view só lê e é grátis. caller é quem chamou.

  2. Confira com tccl check. O compilador verifica tipos, caminhos de retorno e regras de view, e mostra a interface: 
    $ tccl check contador.tccl
✔ Contador compiles (495 bytes of source, 336 bytes compiled)
  state: total: int, ultimo: address
  action incrementar(quanto: int)
  view valor() -> int
  view quem_foi() -> address
  3. Simule com tccl run. Um blockchain de mentira no seu computador, com contas de teste (alice, bob…) que começam com 1.000.000 TCN. O estado fica em tccl-state.json: 
    $ tccl run contador.tccl deploy
deployed Contador at daa436158c1dcdc0242085b6dd9451e33496cbee

$ tccl run contador.tccl call incrementar 5
event Aumentou(quem: tcr1zqygp3t5ugluq2uqf7gq60mc9z9t09lpkg42sa, quanto: 5, total: 5)
ok · fuel used: 1674 · height: 3 · alice balance: 100000000000000 motes

$ tccl run contador.tccl --from bob call incrementar 500
FAILED: requirement failed: no máximo 100 por chamada · fuel used: 33 (all changes reverted)

$ tccl run contador.tccl view valor
result: 5

    Opções úteis: --from <conta>, --value 2.5tcn (para funções payable), --height <n> e @alice como argumento de endereço. Apague tccl-state.json para recomeçar.

  4. Publique com a carteira. A carteira compila, simula no nó para medir o combustível, reserva uma folga, mostra a taxa e pede confirmação: 
    $ thecoin-wallet contract deploy contador.tccl
Fuel:     2475 measured, limit 8217
Action:   deploy contract Contador (495 bytes of TCCL)
Fee:      0.00019697 TCN (654 bytes, priority Normal)
…
Contract address: tc1…

    Opções: --max-deposit (quanto você aceita travar como depósito de armazenamento; padrão 1 TCN), --max-fuel, --value e --priority. Argumentos de init vão depois do arquivo.

  5. Chame uma ação. Também é simulada antes: se fosse falhar, a carteira avisa e não envia nada. 
    $ thecoin-wallet contract invoke tc1… incrementar 5
Fuel:     1777 measured, limit 7310
Preview:  Aumentou(quem: tc1…, quanto: 5, total: 5) (simulated on the current state)
Fee:      0.00012975 TCN (207 bytes, priority Normal)
  6. Consulte. Views não criam transação e não custam nada: 
    $ thecoin-wallet contract view tc1… valor
5
$ thecoin-wallet contract program tc1…     # saldo, armazenamento, depósito e funções

    No Explorer, busque o endereço do contrato: aparecem as funções, o código-fonte, o depósito, os eventos de cada chamada e formulários para chamar as views pelo navegador.

Guia rápido da linguagem

Estrutura de um contrato

# Estrutura de um contrato: constantes, estado, eventos e funções.
contract Cofrinho

const MINIMO: int = 1 * TCN
state dono: address
state nome: text = "Cofrinho"
state depositos: map[address, int]
state valores: list[int]

event Depositou(quem: address, quanto: int)

init():
    dono = caller

action depositar() payable:
    require value >= MINIMO, "depósito mínimo de 1 TCN"
    depositos[caller] += value
    valores.push(value)
    emit Depositou(caller, value)

action sacar(quanto: int):
    require quanto > 0 and depositos[caller] >= quanto, "saldo insuficiente"
    depositos[caller] -= quanto
    send(caller, quanto)

view saldo_de(quem: address) -> int:
    return depositos[quem]

view total_em_caixa() -> int:
    return balance

fn metade(x: int) -> int:
    return x / 2

contract Nomeprimeira declaração; o nome aparece no explorer

state nome: tipo [= valor]dado guardado na blockchain; só tipos simples aceitam valor inicial; mapas só existem aqui
event Nome(campo: tipo, …)registro emitido com emit; aparece no recibo da transação
init(…) [payable]:roda uma vez, na publicação (opcional)
action nome(…) [-> tipo] [payable]:ponto de entrada chamado por transação; pode mudar o estado e enviar TCN
view nome(…) -> tipo:consulta somente leitura, grátis; precisa retornar um valor
fn nome(…) [-> tipo]:função auxiliar interna; só ela pode ser chamada pelo código

Instruções, contexto e funções embutidas

# Controle de fluxo, listas, mapas e funções embutidas.
contract Exemplos

state vistos: map[bytes, bool]
state alturas: list[int]

view soma_pares(n: int) -> int:
    let soma: int = 0
    for i in range(0, n):
        if i % 2 == 0:
            soma += i
        elif i > 1000:
            break
        else:
            continue
    return soma

view maior(xs: list[int]) -> int:
    require len(xs) > 0, "lista vazia"
    let m: int = xs[0]
    for x in xs:
        m = max(m, x)
    return m

view resumo(t: text) -> bytes:
    return slice(sha256(t), 0, 4) + blake3(to_bytes(len(t)))

view rotulo(n: int) -> text:
    return "valor: " + to_text(abs(n))

view assinatura_ok(chave: bytes, msg: bytes, sig: bytes) -> bool:
    return verify_ed25519(chave, msg, sig)

view endereco_da_chave(chave: bytes) -> address:
    return address_of(chave)

action marcar(chave: bytes):
    require not vistos.has(chave), "já marcado"
    vistos[chave] = true
    alturas.push(height)

action desmarcar(chave: bytes):
    vistos.remove(chave)
    let n: int = 0
    while n < 3 and len(alturas) > 0:
        alturas.pop()
        n += 1

Encerrar um contrato

# destroy(): apaga o contrato e devolve saldo + depósito de armazenamento.
contract Temporario

state dono: address
state notas: map[int, text]

init():
    dono = caller

action anotar(n: int, texto: text):
    require caller == dono, "só o dono"
    notas[n] = texto

action apagar(n: int):
    require caller == dono, "só o dono"
    notas.remove(n)

action encerrar():
    require caller == dono, "só o dono"
    destroy(dono)

destroy só funciona depois de esvaziar mapas e listas (variáveis simples são limpas sozinhas). O saldo e todo o depósito de armazenamento vão para o endereço indicado.

Taxas, combustível e depósito — sem mistério

1. Taxa

Paga ao publicar ou chamar, como em qualquer transação: um valor fixo, mais o tamanho em bytes, mais o combustível reservado (max_fuel). É cobrada mesmo se o contrato falhar — o trabalho de executar foi feito.

2. Combustível

Mede o trabalho. Você paga pelo limite que reservou, não pelo que sobrou; por isso a carteira mede com uma simulação e reserva só uma folga (+30% + 5.000). Consultas view não pagam nada.

3. Depósito de armazenamento

Dados na blockchain ocupam disco de todos os nós. Por isso quem faz o contrato crescer trava um depósito por kB. Não é gasto: volta proporcionalmente quando o espaço é liberado, e inteiro no destroy.

A fórmula exata (arredondando para cima):

taxa mínima = (taxa base + bytes × taxa por kB ÷ 1.000 + max_fuel × taxa por mil de combustível ÷ 1.000) × congestionamento
depósito = ⌈bytes do contrato ÷ 1.000⌉ × depósito por kB

Exemplo real: o contador desta página na mainnet

Valores padrão da mainnet: taxa base 1.000 motes, 10.000 motes por kB, 1.000 motes por 1.000 de combustível e depósito de 100.000 motes por kB (1 TCN = 100.000.000 motes). Tamanhos e combustível medidos publicando o contrato numa rede de teste com a versão 0.2; sem congestionamento (1×).

Privacidade com pools de contratos

Como funciona

A The Coin é transparente: saldos e transferências são públicos. Privacidade existe apenas dentro de contratos TCCL escritos por usuários, usando ring_verify — assinaturas em anel ligáveis (bLSAG sobre Ristretto255).

  1. Depósito: você envia o valor fixo do pool (no exemplo, 10 TCN) junto com uma chave pública de anel nova.
  2. Espera: outras pessoas depositam o mesmo valor.
  3. Saque: você assina com um anel formado por vários depósitos. O contrato só aprende que um deles assinou, nunca qual, e paga para um endereço novo. A key image impede sacar o mesmo depósito duas vezes.
  4. Relayer (opcional): outra conta envia a transação de saque e recebe uma pequena taxa, então o endereço de destino não precisa ter TCN antes.

Exemplo completo: private_pool.tccl.

Na carteira

As chaves de anel derivam das suas 24 palavras. A carteira conversa com qualquer pool que siga a interface padrão:

thecoin-wallet privacy keygen --key 0
thecoin-wallet privacy deposit tc1…pool --key 0
thecoin-wallet privacy status tc1…pool --key 0
thecoin-wallet privacy withdraw tc1…pool --key 0 \
    --to tc1…novo --ring-size 16

Interface TCCL-PRIV-1

denomination() -> intvalor fixo do depósito
deposits() -> intquantidade de depósitos
key_at(index: int) -> byteschave pública de um depósito
is_withdrawn(key_image: bytes) -> boolse já foi sacado
message_for(to, relayer, fee) -> bytesmensagem a assinar
deposit(public_key: bytes) payableação de depósito
withdraw(to, relayer, fee, members, signature, key_image)ação de saque
Cuidados. A privacidade é tão boa quanto o número de depósitos no anel: espere outras pessoas depositarem antes de sacar, saque para um endereço que nunca foi usado e, se puder, envie o saque de outra conta ou por um relayer (sacar do mesmo endereço que depositou revela a ligação — a carteira avisa). Pools são contratos de usuários, não parte do protocolo: leia o código-fonte do pool no explorer antes de depositar.
